# 需求对照与验收记录

来源：《新山老人照顾协调服务 创业计划书》第十五节"App 的设计与开发提示词"及相关章节。

## 三种用户与画面

### 长者端（极简、字大、三个按钮）
| 要求 | 实现位置 |
|---|---|
| 紧急求助：按下后把定位和通知同时发给协调员和子女 | `web/src/pages/Elder.tsx` 按住 2 秒 → `POST /api/alerts` 带 GPS → `server/src/events.js` 广播给协调员、家属、长者本人 |
| 我要找人 | 打协调中心电话 / WhatsApp / 显示第二紧急联络人 |
| 看今天的安排 | `GET /api/clients/:id/summary` 今天与接下来的任务 |
| 字体大 | `.elder` 样式：22px 基准，按钮 2 到 2.6rem |
| 警报处理进度回显 | 协调员接手 / 派人 / 结案后，长者页面实时更新状态 |

### 子女端
| 要求 | 实现 |
|---|---|
| 父母的健康档案 | 「健康档案」页（服务器端解密后返回；访问写入审计） |
| 每次探访和看诊的报告 | 「探访报告」页，实时刷新 |
| 照顾人的位置 | 警报带定位，一键打开地图；（照顾人实时轨迹留待手表 / 第二版） |
| 预约服务 | 「预约服务」页，类型：探访、代买药、陪诊接送、物理治疗、用品、钟点工、代买、短期托管 |
| 付费记录 | 「付费记录」页 |
| 家庭群组聊天 | 「家庭群组」页，系统事件自动留痕 |
| 多位长者 | 顶栏切换 |

### 照顾协调员端
| 要求 | 实现 |
|---|---|
| 管理所有客人 | 「客人」：列表、新增、编辑（含健康档案）、关联家属 |
| 分派任务给照顾人 | 「派单」：待安排 / 已安排 / 进行中 / 已完成，指派照顾人或合作伙伴 |
| 记录探访报告 | 「报告」与客人详情页内的报告表单 |
| 管理合作的诊所和护士名单 | 「合作伙伴」：类型、执照号、注册机构、出动时间、价钱 |
| 处理紧急事件并记录处理过程 | 「紧急事件」：实时弹出，已回电 / 派护士 / 派照顾人 / 叫救护车 / 误报 / 结案，每步留时间与人 |
| 手表警报（第十七节流程） | 同上，支持模拟手表触发跌倒 / 心跳 / 走出范围 |
| 低收入补贴与政府援助申请进度（22.6） | 「援助申请」 |
| 合作专业人员资料页含执照号（22.6 / 21） | 「合作伙伴」+ 子女端「照顾团队」 |

### 照顾人端（计划书未单列，但派单流程需要）
我的任务（今天 / 接下来）、开始、导航、客人资料、群组、完成并填报告。

## 技术要求
| 要求 | 实现 |
|---|---|
| 支援中文、英文、马来文 | `web/src/i18n.tsx` 三套字典，网站与 App 均可切换 |
| WhatsApp 或推送通知 | WhatsApp 深链接（wa.me）；App 内 SSE 实时 + 本地通知；FCM 留作下一步 |
| 资料加密，符合个人资料保护法 | AES-256-GCM 字段级加密、访问审计、同意时间戳、免责与隐私页 `/legal` |
| 先做 Android | Capacitor 7 Android 工程 `web/android`，CI 自动出 APK |
| 数据只放在自己的服务器 | 自托管 SQLite + Node，无第三方 SaaS 依赖 |

## 验收（本次开发环境中实际跑过）
- 后端 `npm test`：6 项通过（登录、权限隔离、加密落盘与审计、SOS 流程、派单到报告流程、网站咨询）。
- Playwright 全流程：网站三语切换与咨询表单 → 协调员登录 → 长者按住 SOS → 协调员页面实时出现警报 → 接手、结案 → 长者页面状态变为"已结案" → 子女群组发言、预约 → 照顾人开始任务并提交报告 → 子女群组收到系统消息。浏览器控制台无报错。
- APK：`web/android` 以 Gradle `assembleDebug` 打包（见 README）。
